# Codex Token Status Bar

<img src="assets/app-icon.png" width="96" alt="Codex Token Status Bar icon">

Windows 上附着于 Codex 自带宠物的 credits 状态栏。采用本机已有的 Node.js 24 和 Windows .NET Framework WPF，无第三方生产依赖。

## 下载与环境

从 GitHub Releases 下载 `Codex_Token_Status_Bar-v1.9.0-windows-x64.zip`，解压到固定目录后运行 `Start.cmd`。它会生成带图标的 `Codex + Credits.lnk`，以后可直接使用此快捷方式。ZIP 已包含编译好的挂件，无需先构建。

运行需要 Windows x64、.NET Framework 4.8、Node.js 24+（可在 PATH 中找到）以及已安装并登录的 Codex 桌面客户端。运行数据保存在用户的 LocalAppData 中，发布包不含个人数据。此项目为独立工具，采用 credits 估算消耗、官方百分比表示剩余额度。

## 从源码启动

1. 构建：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1`。
2. 创建启动入口：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Create-Shortcut.ps1`。
3. **完整退出 Codex 后，双击项目根目录的 `Codex + Credits.lnk`。** 该入口同时启动 Codex 和挂件，并仅在本机回环地址开启任务识别接口。
4. 在 Codex 中打开宠物。挂件跟随宠物显示、隐藏和移动；Codex 退出后挂件和数据进程自动退出。

启动器不会强行结束现有 Codex 进程。已经运行的客户端无法补加调试参数，因此首次启用需要退出再打开。建议将此快捷方式固定到常用启动位置。挂件不随 Windows 登录启动。

## 使用

| 控件 | 行为 |
|---|---|
| `−` / `∿` / `≡` | 极简、趋势、详细；再次点击当前展开模式可收起，选择自动保存 |
| 顶部操作栏 | 鼠标移入面板展开，移出后收起；菜单展开期间保留，Tab 键也可唤出；隐藏时移除整行及间距，面板同步缩小 |
| 统计范围 | 位于消耗卡片右侧；当前任务、本机汇总、主要任务、主要项目 |
| 选择任务／项目 | 在比较模式中搜索、复选最多五项并应用；分别记住任务和项目选择，可恢复自动前三 |
| 时间窗口 | 1h、6h、24h、7d、30d；每个范围分为48个等长区间，单位为区间内估算 credits |
| `⋯` | 外观设置：背景不透明度（40%–100%）、浅色／深色，以及薄荷、海蓝、鸢紫、琥珀、玫瑰五种主题色 |
| 任务标题 | 单行省略；点击查看可复制的完整标题，长内容在限定高度内滚动 |
| `!` | 预计额度提前耗尽；简短悬停提示，完整依据位于折叠说明中，不发送系统通知 |
| 顶部两卡 | 周额度剩余、日期＋时段的耗尽预测；提前耗尽时下方黄色提示“！预计提前耗尽 · 3 张重置券”，无券与券数未知分别说明 |
| 消耗数字卡 | 数字下方只保留“时段消耗”或“已选合计”；右侧选择范围及时间，计量说明集中到数据说明 |
| 平滑／原值 | 平滑强度随统计周期变长而降低；滑动曲线时图内上方居中显示“消耗 cr · 速度 cr/min”，下方显示时间段，多曲线显示合计；左右键也可选择区间 |
| 详细面板 | 本机近 1h、24h 两张卡片；“模型使用量”和“其他额度”分开展开，无常驻状态脚注 |
| 右键 | 密度切换、刷新额度、退出挂件 |
| Esc | 收起；图表获得焦点后左右方向键可查看区间 |

跟随动画和平滑曲线尊重 Windows 减少动画设置。平滑模式将五区间加权平均与原值混合，再做单调三次插值；1h、6h、24h、7d、30d 的平滑权重分别为100%、80%、55%、25%、10%。长周期的每个点已经汇总更长时间，因此保留更多原始变化。不跨缺失区间平滑。平滑仅影响趋势外观，区间原值、卡片合计和模型分项不变。同一任务的数据更新使用短时插值过渡，切换任务或时间窗口时直接初始化新曲线。48 个区间与固定时间边界对齐，避免每次刷新重新分桶；末个区间可能尚未结束。

包含无法计价调用的区间没有完整 credit 数值，以半透明虚线直连两端有效点；说明集中在数据与预测说明中。虚线是视觉插值，不补算合计，图内读数以“—”表示无法计算的数值；不会外推首尾缺口，也不会连接不同任务的曲线。单纯没有已记录调用的区间在已有序列中为0，不等于确认整个账户当时没有消耗；完全没有记录的序列保持空白。未结束区间的速度按已过去时长计算。

额度、预测、重置、消耗及详情行的数值变化时，旧文字约110毫秒淡出、新文字约170毫秒淡入。连续更新只显示最新值，相同值刷新保持静止，Windows 关闭界面动画时直接更新。日期时段统一分为凌晨、早上、中午、下午、晚上。

面板展开与收起均使用约220毫秒的高度动画，全程保持背景可见。原生透明窗口保留固定绘制区域，动画只改变其中可见面板的高度，避免反复调整原生窗口尺寸。定位与避让只计算可见面板；其余完全透明区域可点击穿透。标题行按动画进度逐步占用或释放高度，不再立即重排后等待窗口动画追赶；正文与标题行采用独立布局，附着在宠物上方时以正文底边为固定锚点；原生窗口坐标直接依据固定边缘计算，避免两个动画高度参与坐标差值。连续操作采用最新目标，Windows 关闭界面动画时直接调整。透明度拖动仅修改现有半透明画刷，静止200毫秒或松开滑块后合并保存；退出时提交最后一次调整。外观设置使用轻量确认消息，不重新计算统计数据。下拉选择框使用主题色半透明底色；展开菜单使用随不透明度设置变化的独立背景。

面板通常位于宠物上方，并避开原生浮动条；上方空间不足时改到下方，靠近左右边缘只做横向偏移；不再停靠宠物的左侧或右侧。上下均放不下时，选择空间更大的一侧限制面板高度并启用内部滚动，恢复空间后释放高度限制。拖拽跟随由 WPF 渲染帧驱动，进程发现移到后台；静止时不反复移动或提高窗口层级，因此展开菜单不会再被面板盖住。换方向统一使用约280毫秒的淡出、透明期间换位、淡入；不再绕宠物移动。返回上方要求额外空间余量，该余量随标题栏高度与缩放比例变化，避免标题展开／收起反复触发上下翻转。多显示器定位使用原生物理坐标和宠物 DOM 局部坐标，支持负坐标与缩放比例。

## 数据口径

### 官方剩余额度

通过 Codex 官方 App Server 的 `account/rateLimits/read` 获取主 `codex` 额度池。按窗口长度识别周额度，不假设 `primary` 就是五小时。剩余量保留官方百分比；接口没有给出订阅周额度总 credits，不能编造换算。

其他额度池在详细面板各占一行。没有可用数据源的 ChatGPT Pro 剩余消息次数已删除。

重置券数量直接读取同一接口的 `rateLimitResetCredits.availableCount`；0 张与暂不可用分开显示，随额度采样刷新。提前耗尽时券数并入预测说明，仅展示，不执行兑换。额度重置时间保留在详细面板，按官方时间戳显示；耗尽预测主动降低精度，以日期和时段表达。

### 消耗统一为估算 credits

每个模型调用按当前版本官方费率计算：

```text
((输入 − 缓存输入) × 输入费率 + 缓存输入 × 缓存费率 + 输出 × 输出费率)
÷ 1,000,000 × 已知的 Fast 倍率
```

- 缓存输入是总输入的子集，推理输出是总输出的子集，均不重复累加。
- 按调用当时的模型计算，不把线程累计量全部套用当前模型。
- 缺少速度档位记录时按标准费率估算，并在界面注明；未知模型、未知档位或未明确计费的缓存写入记为缺失，合计明确为已知部分。
- 费率表版本为 **2026-09-16-r1**。历史曲线用该版本费率重新估算，不宣称复原历史账单；Sol 当前价格为促销费率。
- 用户确认的模型映射：`codex-auto-review` 按 `gpt-5.4`，`gpt-reserve` 按 `gpt-5.6-luna` 估算，使用对应模型的输入、缓存、输出与速度倍率。此对应关系来自用户确认，独立记录于费率表，不标为官方映射。
- 调用日志提供 token 用量，不提供这些模型的单价。确认同一模型的费率后，提高费率表版本会重新读取本机历史并回算；后续其他模型的费率不会自动覆盖未知模型。
- 本机汇总包含本机可读日志；**不等于整个账户所有设备的完整消耗**。官方每日总 token 缺少模型和缓存分项，因此没有伪造账户每日 credits 曲线。
- 官方 `account/usage/read {threadId}` 如果返回 `threadUsage.estimatedUsageCreditsMicros`，在详情中单列该任务的服务端累计估算，不与本机区间量相加。该数据与当前选择的时间窗口含义不同。
- 只展示最近35天已索引记录范围内的数据。删除的历史、未同步的远端任务、工具额外费用可能不在其中；当前远端任务没有本地记录时不冒充本地任务。

### 单一耗尽预测

从实际额度百分比变化学习活跃工作速率，以历史小时级活跃概率估计未来工作时长，再由近期速度修正。输出一个耗尽时间，或“预计可用至重置”。预测是对已观察行为的估计，不是保证。

- 至少需要两个有活动记录的日期、一小时连续额度采样、两个百分点的可观察变化。
- 不跨采样中断或额度重置推算瞬时速度；额度数据超过5分钟未更新时暂停预测。
- 后台每30秒刷新额度、每10秒增量索引本机日志、每秒识别当前任务。宠物几何信息独立以40毫秒间隔采样，显示时原生跟随由渲染帧驱动，不触发额度或图表重算；隐藏时用低频计时器检测恢复。
- 只在 Codex 运行期间采样。界面隐藏仍采样；客户端退出停止采样。多设备消耗会降低预测可靠性。

## 当前任务识别与附着

通过本机 CDP 读取输入框的 `data-above-composer-conversation-id`。该标记自身可以没有布局尺寸；可见性与焦点由 `[data-codex-composer-root]` 容器判断，隐藏的缓存输入框仍被排除。优先当前获得焦点的 Codex 页面；切到其他应用时保留最后查看任务。识别失败时标明使用最近活跃任务。子代理按父任务归组。

任务名称采用 `session_index.jsonl` 中时间最新的 `thread_name`，与 Codex 重命名同步。SQLite 的 `title` 可能只是首条提示词，因此不再用作显示名称；没有名称时显示中性的任务 ID。索引刷新时会更新重命名，不需要重建 credits 缓存。

宠物使用 `[data-testid="avatar-mascot-button"][data-avatar-mascot="true"]` 的稳定容器边界，而不是每帧变化的美术像素或透明窗口整体。通过 Codex 进程、窗口类和工具窗口样式识别唯一宠物窗口；不再要求拖拽中的 DOM 尺寸与原生窗口同步。原生浮动条的可见交互区域作为避让障碍物。短暂采样失败保留上一次几何信息；子元素的隐藏事件不会被误判为整个宠物关闭。这些内部 DOM 标记可能随 Codex 升级而变化，需兼容性验证。

## 项目结构

```text
src/backend/    官方接口、本机增量索引、credits 核算、预测、CDP 元数据
src/windows/    WPF 窗口、UsageView 类型化数据、BackendClient 异步通信、SettingsCommitter 设置合并
                图表、主题、AnimatedLayout 高度过渡、HeaderBodyPanel 正文锚定、跟随与避让
assets/         应用图标与生成说明
scripts/        构建、启动、快捷方式生成、打包、真实数据 smoke 检查
tests/          核算与增量读取测试、独立演示数据
build/          构建产物（不入 Git）
dist/           Windows 发布 ZIP（不入 Git）
artifacts/      测试结果与渲染预览（不入 Git）
prev/           旧版本，按授权仅参考任务识别思路及 2.15 预览图的卡片视觉设计
```

本机设置、额度历史和仅含用量的索引缓存位于 `%LOCALAPPDATA%\CodexPetCredits`。应用不读取认证文件，不存储提示词或聊天正文。日志中的任务标题和项目路径仅用于本机界面；不会上传到外部统计服务。

## 验证

```powershell
node --test tests/*.test.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-Frontend.ps1
node scripts/Smoke.mjs
.\build\CodexPetCredits.exe --render "$PWD\artifacts\previews"
```

`Smoke.mjs` 只读连接真实 Codex 账户，输出额度可用性与用量记录计数；不触发模型推理。渲染使用明确标记的演示数据，产出六种密度／明暗组合、十种展开详情与外观面板的主题预览、两种缺口虚线预览、两种图内读数预览及隐藏标题栏预览。

当前已完成18项数据测试、32项前端回归测试、WPF 构建及21种界面渲染。新增覆盖空图时间轴更新、重置时间可见性、仅上下附着与高度受限、透明度资源复用和提交合并，以及真实 Node 子进程中的消息顺序与退出提交。标题测试使用与正式程序相同的 PerMonitorV2 清单和配置，在125%缩放屏幕逐帧检查正文屏幕坐标与文字像素；保留150%布局、透明区域点击穿透和此前交互回归。用户报告的轻微抖动未直接复现；新布局加强了正文锚定，当前测试偏移为0.000像素，不代表所有屏幕组合均已验证。

`scripts/Probe-Frontend.ps1 -BinaryDirectory build-next` 在真实宠物附近运行独立测试面板，检查两个下拉菜单的原生窗口遮挡、选项选择，并在同一显示器内回放移动锚点以及展开／收起，验证收起期间原生绘制区域不变、背景始终可见；不注入鼠标输入，也不移动真实宠物。运行前须关闭旧版挂件，避免其抢占层级干扰。性能测量只代表当前设备的短时表现，不保证所有显示器或负载下固定帧率；不同缩放屏幕之间的真实拖动仍待使用验证。

### 可重复的性能检查

`scripts/Measure-Frontend.ps1 -BinaryDirectory build-next` 运行固定操作次数的UI线程基准，取五轮中位数。本机本轮测量：120次透明度调整从约18.1ms降到约0.7–1.3ms；同一图表区间内10000次悬停处理从约29.5ms降到约0.02ms。前者避免全界面重建，后者在选中区间未变化时直接返回；实际新数据仍刷新读数。此基准不包括后台磁盘耗时，也不是帧率承诺。退出时后台写入队列最多等待300ms排空，正常操作不在UI线程写管道。

打包：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Package.ps1 -BinaryDirectory build-next`。脚本使用明确的发布目录清单，不读取 `prev` 或本机运行数据。
